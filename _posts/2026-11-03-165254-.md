### 三、变量和字符串：有没有引号，含义不同

最初的例子只有三行：

```python
question = "什么是人工智能？"
message = {"role": "user", "content": question}
print(message["content"])

```

第一行把一段字符串保存到变量 `question`。第二行用这个变量里的值创建消息。第三行取出消息内容并打印。

一个后来反复用到的区别是：

```python
question       # 使用变量中保存的值
"question"     # 固定的文字 question

```

例如：

```python
question = "教我学 Python"

print(question)
print("question")

```

输出分别是：

```text
教我学 Python
question

```

在模型消息中，如果把 `content=question` 写成 `content="question"`，发送出去的就会是固定文字，而不是用户实际输入的问题。

### 四、字典：表示一条消息

一条聊天消息可以用字典表示：

```python
message = {"role": "user", "content": "你好"}

```

其中：


| 键 | 值 | 含义 |
| --------- | ------ | ------- |
| `role` | `user` | 消息来自用户 |
| `content` | `你好` | 消息的文字内容 |


按键读取值：

```python
print(message["role"])
print(message["content"])

```

输出：

```text
user
你好

```

也可以修改某个键对应的值：

```python
message["role"] = "assistant"
message["content"] = "你好，有什么可以帮你？"

```

我还区分了几种打印方法：

```python
print(message)                              # 打印整个字典
print(message["content"])                   # 只打印内容
print(message["role"], message["content"])  # 打印角色和内容

```

`print(message)` 本身没有问题，只是输出范围与“只打印消息内容”不同。

### 五、列表：按顺序保存多条消息

一个字典表示一条消息，多个消息可以放进列表：

```python
messages = [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好，有什么可以帮你？"}
]

```

外层 `[]` 是列表，里面每一个 `{}` 是消息字典。

Python 从 `0` 开始编号：

```python
messages[0]              # 第一条消息
messages[1]              # 第二条消息
messages[-1]             # 最后一条消息
messages[0]["content"]   # 第一条消息的内容

```

向列表末尾添加消息：

```python
messages.append({"role": "user", "content": "教我学 Python"})

```

查看数量：

```python
print(len(messages))

```

这里我解决了一个最初的疑问：必须先创建列表，才能调用它的 `append()`。

```python
messages = []
messages.append({"role": "user", "content": "你好"})

```

如果后面重新执行 `messages = []`，这个变量就会指向一个新的空列表。做聊天历史时，要特别留意初始化的位置。

### 六、循环、判断与用户输入

使用 `for` 可以逐条处理消息：

```python
for message in messages:
    print(message["role"], message["content"])

```

这里的 `message` 是每次循环取出的一个元素，也就是一个消息字典。

只显示用户消息，可以加判断：

```python
for message in messages:
    if message["role"] == "user":
        print(message["content"])

```

需要区分赋值与比较：

```python
message["role"] = "user"   # 赋值
message["role"] == "user"  # 比较是否相等

```

`input()` 会等待终端输入，按回车后返回字符串：

```python
question = input("请输入问题：")

```

把它们组合起来，就有了一个持续接收问题的小程序：

```python
messages = []

while True:
    question = input("请输入问题，输入 exit 退出：").strip()

    if question == "exit":
        break

    if question == "":
        continue

    messages.append({"role": "user", "content": question})

for message in messages:
    print(message["role"], message["content"])

```

几个关键点：

- `while True` 持续循环。
- `break` 结束循环。
- `continue` 跳过本轮剩余代码，进入下一轮。
- `.strip()` 去掉字符串两端的空白，不会删除正文中间的空格。
- Python 使用缩进表示代码块，所以循环内外的位置会影响执行时机。

这段程序只保存和打印输入，还没有调用模型。

### 七、函数：定义与调用要分清

把“创建一条消息”写成函数：

```python
def make_message(content, role="user"):
    return {"role": role, "content": content}

```

其中：

- `def` 定义函数。
- `content` 和 `role` 是参数。
- `role="user"` 设置默认值。
- `return` 把结果返回给调用者。

调用时：

```python
msg = make_message("你好")

```

因为没有指定 `role`，得到：

```python
{"role": "user", "content": "你好"}

```

显式指定角色：

```python
msg = make_message("你好，有什么可以帮你？", role="assistant")

```

也可以全部使用关键字参数：

```python
msg = make_message(role="assistant", content="你好")

```

我练习时曾把“调用现有函数”写成重新定义一个函数。后来才分清：

```python
def make_message(content, role="user"):  # 定义
    return {"role": role, "content": content}

make_message("你好")  # 调用

```

函数返回值还可以直接交给另一个方法：

```python
messages.append(make_message("什么是函数？"))

```

执行顺序是先创建字典，再把字典追加到列表中。

另外，`print()` 和 `return` 的作用不同：前者显示内容，后者把结果交给调用者。

### 八、JSON：把内存中的数据保存下来

Python 字典和 JSON 字符串看起来相似，但类型不同。

```python
import json

message = {"role": "user", "content": "你好"}

text = json.dumps(message, ensure_ascii=False)
data = json.loads(text)

```

这段转换过程是：

```text
Python 字典 → dumps() → JSON 字符串
JSON 字符串 → loads() → Python 字典

```

`ensure_ascii=False` 让中文直接显示出来。如果使用默认设置，中文可能写成 `\u4f60\u597d` 这样的转义形式；解析回来后，表示的仍然是“你好”。

涉及文件时，使用另一对函数：

```python
with open("messages.json", "w", encoding="utf-8") as file:
    json.dump(messages, file, ensure_ascii=False, indent=2)

with open("messages.json", "r", encoding="utf-8") as file:
    loaded_messages = json.load(file)

```


| 函数 | 用途 |
| --------- | ---------------- |
| `dumps()` | 把数据编码为 JSON 字符串 |
| `loads()` | 从 JSON 字符串解析数据 |
| `dump()` | 把数据以 JSON 格式写入文件 |
| `load()` | 从文件中解析 JSON 数据 |


这里还学到了：

- `"w"` 表示写入，已有文件会被覆盖。
- `"r"` 表示读取。
- `encoding="utf-8"` 指定文本编码。
- `indent=2` 让保存的 JSON 更便于阅读。
- `with` 语句会在代码块结束时关闭文件。
- 相对路径按程序运行时的当前工作目录解析，不一定就是脚本所在目录。

保存后再读取，是为了确认数据确实进入了文件，而不仅仅是还保存在原变量中。

### 九、类与对象：把数据和操作放在一起

我先实现了一个管理消息的类，再把 JSON 保存与读取加入其中。

下面是整理后的完整练习代码。它是本次 Python 基础教学练习，不是训练营官方 Agent 作业的完成答案：

```python
import json


class MessageHistory:
    def __init__(self, system_prompt):
        self.messages = [
            {"role": "system", "content": system_prompt}
        ]

    def add(self, content, role="user"):
        self.messages.append(
            {"role": role, "content": content}
        )

    def save(self, filename):
        with open(filename, "w", encoding="utf-8") as file:
            json.dump(
                self.messages,
                file,
                ensure_ascii=False,
                indent=2,
            )

    def load(self, filename):
        with open(filename, "r", encoding="utf-8") as file:
            self.messages = json.load(file)


history = MessageHistory("你是 Python 助教")
history.add("什么是字典？")
history.save("python_messages.json")

history1 = MessageHistory("临时提示")
history1.load("python_messages.json")

for message in history1.messages:
    print(message["role"], message["content"])

```

这组练习中，我实际完成并确认运行成功了保存、读取和循环打印。

#### 1. `class`、对象和属性

```python
history = MessageHistory("你是 Python 助教")

```

`MessageHistory` 是类，调用它创建对象，变量 `history` 指向这个对象。

`history.messages` 是对象的属性；`history.add(...)` 是调用对象的方法。

#### 2. `__init__` 与 `self`

创建对象时，Python 自动执行初始化方法：

```python
def __init__(self, system_prompt):

```

`self` 指向当前对象，调用方法时由 Python 自动传入。`system_prompt` 则由创建对象时传入。

#### 3. 每个对象有自己的列表

因为列表是在初始化方法中分别创建的，所以两个对象可以保存不同的消息：

```python
history1 = MessageHistory("你是 Python 助教")
history2 = MessageHistory("你是一位数学老师")

```

向 `history1` 添加消息，不会直接添加到 `history2` 的列表中。

#### 4. `load()` 是替换记录

```python
self.messages = json.load(file)

```

这句会用文件中的数据替换当前对象的消息列表。因此，示例中第二个对象最初的“临时提示”，会被加载的记录替换。

这个练习按自己生成的 JSON 文件读取；它还不是面向任意外部文件的完整聊天记录产品。

### 十、异常：发现错误与处理错误

我写了一个问题检查函数：

```python
def check_question(question):
    question = question.strip()

    if not question:
        raise ValueError("问题不能为空")

    return question

```

`raise` 主动抛出异常。这里先清理两端空白，再检查内容，避免几个空格被当成有效问题。

在用户输入的位置处理这个异常：

```python
while True:
    try:
        question = input("请输入问题：")
        question = check_question(question)
        print("收到问题：", question)
        break
    except ValueError as error:
        print("输入有误：", error)
        print("请重新输入")

```

有效输入会打印并退出；无效输入会提示并重新开始下一轮。

这里使用 `try/except` 有明确目的：让用户纠正输入。不是所有代码都需要机械地包一层异常捕获。

### 十一、模块导入：一次真实的排错经历

我把 `check_question()` 放进 `helpers.py`，然后在另一个文件中使用：

```python
from helpers import check_question

```

两个文件放在同一个练习目录中，导入时不写 `.py`。

运行时，我遇到了这个错误：

```text
NameError: name 'awd' is not defined

```

终端进一步指出，错误发生在 `helpers.py` 第 1 行，那里有一段多余的 `awd`。

这说明 Python 已经找到了模块，但导入过程中执行模块顶层代码时出错了。删除多余内容、保存文件，再运行调用文件后，导入和函数调用成功。

这次我记住了一个排错顺序：

1. 看错误最后一行，确定异常类型和含义。
2. 往上找具体文件及行号。
3. 检查对应代码，并确认编辑器中的修改已经保存。
4. 重新运行，观察结果。

### 十二、环境变量：模型配置从哪里来

课程使用环境变量读取连接信息：

```python
import os

model = os.getenv("MODEL_ID", "未配置模型")

```

变量不存在时，返回给定的默认值。不提供默认值时，变量不存在会返回 `None`。

我还学习了几种容易混淆的值：


| 写法 | 含义 |
| -------- | ----- |
| `None` | 没有值 |
| `"None"` | 固定字符串 |
| `""` | 空字符串 |


对于这里读取到的配置，可以这样检查：

```python
if not model:
    print("需要配置")
else:
    print("模型名称已填写")

```

Demo 中的密钥选择写法是：

```python
API_KEY = os.environ.get("API_KEY") or os.environ.get("CNB_TOKEN") or ""

```

理解为从左到右选择第一个非空值即可：先尝试 `API_KEY`，再尝试 `CNB_TOKEN`，最后使用空字符串。

### 十三、第一次读懂模型调用代码

回到课程的 `demo_00_chat.py` 后，我终于能把它和前面的基础知识对应起来。

#### 1. 创建客户端对象

```python
from openai import OpenAI

client = OpenAI(
    base_url=BASE_URL,
    api_key=API_KEY,
)

```

这和创建 `MessageHistory` 对象的形式相似：把配置作为参数传给类，得到客户端对象。

课程使用 OpenAI Python SDK 的接口形式，实际请求地址由 `base_url` 决定。不能仅凭库名就判断请求一定发往 OpenAI 官方服务。

#### 2. 发起一次请求

```python
stream = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "user", "content": user_input}
    ],
    temperature=0.9,
    stream=True,
)

```


| 参数 | 我目前的理解 |
| ------------- | ----------- |
| `model` | 选择本次请求使用的模型 |
| `messages` | 本次发送的消息列表 |
| `temperature` | 影响输出采样的随机程度 |
| `stream=True` | 以增量片段接收回复 |


模型名称是否可用、参数是否受支持，要看具体服务与权限。默认名称是代码里的配置值，不代表任何环境都一定可用。参数说明可参考 [OpenAI 官方接口文档](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)。

#### 3. 理解流式输出

流式返回时，程序陆续接收多个片段，而不是只处理一次性返回的完整字符串。片段通常叫 `chunk`，一个片段不一定是一个字或一个 token。

Demo 中这段代码取出当前新增的正文：

```python
text = chunk.choices[0].delta.content

```

可以分层理解：

```text
chunk：本次响应片段
   ↓
choices：候选结果列表
   ↓
[0]：第一个候选结果
   ↓
delta：本次新增的信息
   ↓
content：新增的正文文字

```

有些片段可能没有正文，因此代码先检查再处理。[官方流式说明](https://developers.openai.com/api/docs/guides/streaming-responses)

随后执行：

```python
print(text, end="", flush=True)
parts.append(text)

```

这两行同时完成“显示”和“保存”：

- `end=""` 让输出片段接在同一行。
- `flush=True` 立即刷新输出。
- `parts.append(text)` 把片段保存到列表。

最后：

```python
return "".join(parts)

```

把所有片段连接成完整回复并返回。例如：

```python
parts = ["你好", "，我是", "你的助手。"]
answer = "".join(parts)

```

`answer` 就是 `"你好，我是你的助手。"`。

`chat()` 因此既有打印过程，也有返回值。原始 Demo 的主循环调用它时，没有用变量接住返回值，但屏幕上仍然会看到函数内部打印的回复。

#### 4. `__main__` 入口

```python
if __name__ == "__main__":

```

直接运行文件时，执行下面的输入循环；被其他文件导入时，不进入这个入口块。

需要注意，入口块外的顶层代码仍会在导入时执行。这一点与前面 `helpers.py` 的排错经历可以联系起来理解。

### 十四、我实际做出的改动：加入 system 消息

这次，我在课程 Demo 的请求中加入了 system 消息：

```python
messages=[
    {
        "role": "system",
        "content": "你是 Python 助教，用简短中文和小例子回答。"
    },
```

### 十五、这次出现过的几个具体错误

除了模块导入错误，我还出现过一些初学阶段容易忽略的小问题。


| 我写过的内容 | 问题 | 修正或理解 |
| ------------------------------------------ | --------------------- | --------------------------------- |
| `{"role": "assistant", "content": "..."};` | 在 `append()` 参数位置多写分号 | 删除多余分号 |
| `ensure_ascii=False.indent=2` | 两个参数之间写了点号 | 改为 `ensure_ascii=False, indent=2` |
| `encoding="utf=8"` | 编码名称写错 | 改为 `encoding="utf-8"` |
| 循环变量写 `mesage`，打印时用 `message` | 前后变量名不一致 | 统一名称 |
| 代码行末尾出现中文顿号 `、` | 不符合该位置的 Python 语法 | 删除中文标点 |
| `MessageHistory("")` | 创建了一条内容为空的 system 消息 | 按任务填写实际角色提示 |
| 保存后仍遍历原来的 `messages` | 没有直接检查读回的数据 | 遍历 `loaded_messages` |
| 把变量写成 `"question"` | 使用了固定文字 | 需要用户输入时使用 `question` |


我发现很多问题不是整段流程想错了，而是标点、变量名、参数或运行位置不一致。检查时要把这些小细节与程序整体逻辑分开看。

### 十七、下一步：让模型请求携带历史消息

下一步计划是把前面的消息管理与真实模型调用连接起来。

希望第二次请求中包含这样的消息序列：

```text
system
user：第一轮问题
assistant：第一轮回复
user：第二轮问题

```

实现思路：

1. 在输入循环外初始化一次 `messages`。
2. 每次输入后，追加一条 user 消息。
3. 把完整列表传给 `chat()`。
4. 接住 `chat()` 返回的完整回复。
5. 把回复作为 assistant 消息追加到同一列表。
6. 下一次请求继续使用累积后的历史。

验证时，除了问“我刚才说了什么”，还要检查请求前的消息列表是否真的包含前面的问答。不能只凭模型碰巧回答正确，就判断历史管理已经实现。

这一步完成后，再尝试把 JSON 保存读取接上，让聊天记录在程序重启后也能够恢复。它们都是后续练习计划，尚未作为本次已完成成果。
